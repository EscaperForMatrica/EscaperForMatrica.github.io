# PALADA — интернет-магазин

Реализация макетов «PALADA — макеты интернет-магазина» (41 артборд: дизайн-система, витрина, корзина, оформление, оплата, вход (в макетах — по СМС, в магазине — по коду на почту), кабинет, админка, документы, пустые состояния, опт).

**Стек:** [Astro 7](https://astro.build) в режиме SSR (Node-адаптер) + встроенный в Node SQLite (`node:sqlite`). Без клиентских фреймворков и нативных зависимостей; на клиенте — небольшие скрипты на TypeScript.

## Запуск

```bash
npm install
npm run dev          # http://localhost:4500
```

Production:

```bash
npm run build
npm start            # node ./dist/server/entry.mjs, порт задаётся PORT (по умолчанию 4321)
```

Нужен Node 22.13+ (проверено на Node 26). База `data/palada.db` создаётся при первом запуске: только каталог и администратор, без заказов, покупателей и промокодов. Для разработки можно заполнить тестовыми покупателями и заказами: `SEED_DEMO=true` в `.env` и `npm run db:reset`.

В production (`npm start`) код входа никогда не показывается на странице, тестовая оплата отключена, а cookie сессии ставятся с флагом `Secure` — сайт должен работать по HTTPS (например, за nginx/Caddy). Администраторы берутся из `ADMIN_EMAILS` (если не задан — почта заказчика arm2730@mail.ru). Пока не настроен SMTP, коды входа видны только в логе сервера (`[mail:dev] …`), а без ключей ЮKassa оформление честно сообщает, что онлайн-оплата не подключена.

## Вход

Вход везде — по почте и коду из письма, пароля нет. Админка открывается по секретному адресу из `ADMIN_PATH` (в разработке — `/admin`), на боевом сайте `/admin` — «страница не найдена». Администраторы — адреса из `ADMIN_EMAILS` (по умолчанию arm2730@mail.ru); других сотрудников можно добавить в админке. Пока почта (SMTP) не настроена, код пишется в лог сервера, а в разработке и демо — показывается прямо на странице входа.

С `SEED_DEMO=true` тестовая база получает покупателя anna@palada.demo, компанию zakupki@palada.demo и промокоды из макета (`PALADA10`, `PERVYI300`, `OPT5`, недействительные `SALE2024` и `LETO20`).

## Что работает

- **Витрина:** главная, каталог (категории, поиск, сортировка, «Показать ещё»), карточка товара (галерея, вкладки, «С этим покупают»), избранное (и для гостей — переносится в кабинет при входе).
- **Корзина:** количество, удаление, промокоды с правилами (сроки, минимальная сумма, лимит, «один раз на покупателя»), экономия к старым ценам.
- **Оформление:** контакты, ПВЗ Ozon на карте/списком с ценой и сроком, ПВЗ Wildberries по адресу, обязательные согласия, выбор оплаты (карта/СБП), экраны «оплата прошла / не прошла» с повтором.
- **Кабинет:** вход и регистрация по коду из письма, заказы со статусами и трек-номерами, «Повторить заказ», профиль, рассылка, отзыв согласия, смена почты по коду.
- **Опт:** регистрация компании по ИНН (проверка контрольных цифр + реквизиты), оптовый каталог в коробках, счёт на юрлицо (страница для печати/PDF) или онлайн-оплата, кабинет компании с документами.
- **Админка** (`/admin`): обзор (выручка с графиком, сравнение с прошлым периодом, что требует внимания, лидеры продаж), заказы (фильтры, карточка-шторка, трек-номер, статусы, загрузка УПД, выгрузка CSV), товары (поиск, фильтры, массовые действия, редактор с фото, оптовые цены), категории, клиенты и компании с историей заказов, промокоды, администраторы (добавление по почте), настройки (контакты, реквизиты и банк для счетов, почта для уведомлений).
- **Письма:** код входа, «заказ оплачен» покупателю и магазину, трек-номер, выставленный счёт.
- **Адаптив:** десктоп 1440 и мобайл 390 — по своим артбордам (таб-бар, мобильные шапки, шторки, липкие панели), промежуточные ширины — плавно.

## Демо на GitHub Pages

**Сейчас не публикуется:** escaperformatrica.github.io переадресует на https://palada.shop с сохранением пути (папка `pages-redirect`, её выкладывает `.github/workflows/pages.yml`). Её `sw.js` снимает прежний service worker демо и удаляет демо-данные у тех, кто открывал демо раньше. Ниже — как устроена демо-сборка, если она снова понадобится.

GitHub Pages умеет отдавать только статические файлы, поэтому для него есть отдельная сборка `npm run build:pages`: серверная часть Astro вместе с базой SQLite (sql.js, WebAssembly) упаковывается в service worker `sw.js` и работает прямо в браузере посетителя. Страницы и API рендерятся тем же кодом, что и на сервере, — работает всё: корзина, оформление, тестовая оплата, вход по коду, кабинет, опт и админка.

Особенности демо:
- данные (заказы, корзина, изменения в админке) хранятся в IndexedDB браузера посетителя и видны только на этом устройстве;
- включён демо-режим: код входа показывается на экране (письма не отправляются), оплата тестовая;
- нужен браузер с поддержкой Service Worker (все современные; в приватном режиме Firefox не работает).

Локальная проверка: `npm run fonts && npm run build:pages`, затем раздать папку `dist-pages/client` любым статическим сервером на `localhost`.

## Боевой сайт на хостинге lite-host

Магазин работает на cPanel-хостинге lite-host как Node.js-приложение под Phusion Passenger (Node 24 из `/opt/alt/alt-nodejs24`). Демо-режим выключен: коды входа и письма о заказах уходят с ящика магазина info@palada.shop (почта домена на том же хостинге, SPF и DKIM настроены cPanel). Уведомления о заказах и коды входа администратора приходят на arm2730@mail.ru.

- `~/palada-app` — приложение: `dist/`, `app.cjs` (точка входа для Passenger), `package.json`, `node_modules`, `.env` с боевыми настройками (в репозиторий не попадает).
- `~/palada-data` — база `palada.db` и загруженные фото (`uploads/`); выкладка их не трогает.
- `~/palada.shop/.htaccess` (и `~/palada.su/.htaccess`) — подключение домена к приложению (`PassengerAppRoot`, `PassengerNodejs`, `PassengerStartupFile app.cjs`). Панель «Setup Node.js App» на сервере отключена хостером, поэтому приложение подключено напрямую через `.htaccess`.

Выкладка новой версии — одной командой (нужен SSH-доступ к хостингу): `DEPLOY_HOST=<ssh-хост> sh scripts/deploy.sh`. Скрипт собирает сайт, заливает `dist/`, ставит зависимости и перезапускает приложение (`tmp/restart.txt`).

Адрес магазина — **https://palada.shop** (домен в REG.RU, DNS-серверы `ns3.lite-host.in` и `ns4.lite-host.su`, записи зоны ведёт cPanel). Сертификат Let's Encrypt для palada.shop и www.palada.shop выпускает и продлевает AutoSSL. В `~/palada.shop/.htaccess`, кроме подключения приложения, — переадресация всего на `https://palada.shop` без www (кроме `/.well-known/` для проверок AutoSSL). Старый palada.su (у ihc.ru) можно позже перенаправить на palada.shop.

Письма отправляются через SMTP хостинга: в `~/palada-app/.env` — `SMTP_HOST=mars.lite-host.in`, `SMTP_PORT=465`, `SMTP_USER`/`SMTP_FROM` — info@palada.shop, `SMTP_PASS` — пароль этого ящика (создан в cPanel → «Почтовые учетные записи»). После правки `.env` перезапустить приложение: `touch ~/palada-app/tmp/restart.txt`.
Затем войти в `/admin` с arm2730@mail.ru — код придёт на почту. В «Настройках» нажать «Отправить тестовое письмо».

Потом в `.env` добавляются ключи ЮKassa (`YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`) и DaData (`DADATA_API_KEY`). Пока ключей ЮKassa нет, оформление честно сообщает, что онлайн-оплата не подключена, и предлагает написать в WhatsApp.

## Скорость и безопасность

- **Статика** (`/_astro`, `/images`, `/fonts`) лежит в корне сайта и отдаётся веб-сервером хостинга без Node: файлы сборки и шрифты кэшируются на год, картинки — на 30 дней. Node рендерит только страницы (≈20 мс на сервере).
- **Картинки:** у каждого фото каталога есть копия 480 px (`scripts/image-variants.mjs`, запускается при выкладке); карточки берут её через `srcset`, первые карточки и баннер грузятся с высоким приоритетом. Фото, загруженные в админке, сразу переводятся в WebP до 1000 px с копией 480 px.
- **CSS** встроен в страницу (`build.inlineStylesheets`), скрипты — только файлами из `/_astro`.
- **Заголовки безопасности** (по образцу helmet и OWASP Secure Headers): Content-Security-Policy без внешних источников и inline-скриптов, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, COOP; версия Passenger скрыта. Админка и API отдаются с `X-Robots-Tag: noindex`.
- **Вход:** коды хранятся только хэшем, на код 3 попытки, на почту — 5 кодов в час, с одного IP — 10 кодов в час (IP берётся из адреса, который дописывает прокси хостинга, подделать его заголовком нельзя). Возврат после входа — только на страницы этого сайта.
- **Зависимости:** `npm audit --omit=dev` — 0 уязвимостей (nodemailer обновлён до 10.x).

## Настройки (`.env`, см. `.env.example`)

| Переменная | Что делает |
|---|---|
| `SITE_URL` | Домен — для canonical и ссылок возврата из платёжки |
| `ADMIN_PATH` | Секретный адрес админки (на боевом сайте задан только в `.env` сервера). С ним `/admin` для всех отдаёт «страница не найдена» |
| `ADMIN_EMAILS` | Почта администраторов через запятую, по умолчанию arm2730@mail.ru (остальных можно добавить в админке) |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Боевая оплата через ЮKassa (карта и СБП). Пусто — тестовая страница оплаты `/pay/test` (отключена в production) |
| `YOOKASSA_RECEIPTS`, `YOOKASSA_VAT_CODE` | Передача чека по 54-ФЗ и код ставки НДС |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Почта: коды входа и письма о заказах |
| `DADATA_API_KEY` | Реквизиты компании по ИНН через DaData. Пусто — тестовые реквизиты |
| `DEMO_MODE` | `true` — витрина для показа (сборка GitHub Pages): код входа на экране, тестовая оплата, база пересоздаётся при обновлении. На боевом сайте не включать — с ним любой может войти под любой почтой, в том числе в админку |
| `SEED_DEMO` | `true` — заполнить новую боевую базу демо-покупателями и заказами |
| `DB_PATH` | Путь к файлу базы (по умолчанию `data/palada.db`) |

Для ЮKassa укажите в её кабинете URL уведомлений `https://<домен>/api/payments/yookassa` — статус платежа дополнительно перепроверяется запросом к API.

## Перед запуском в работу

- **Шрифт Tilda Sans** в репозитории не хранится: `npm run fonts` скачивает официальный веб-пакет с CDN Тильды ([tilda.cc/ru/lp/tildasans](https://tilda.cc/ru/lp/tildasans/)) и кладёт Regular, Medium, Semibold и Bold в `public/fonts/`. Скрипт выкладки `scripts/deploy.sh` делает это сам. Без шрифта сайт показывается запасным Arial.
- **Пункты выдачи Ozon** сейчас — справочник в `src/lib/delivery.ts` (14 городов, демо-адреса). Для работы замените `getPoints()` на API Ozon Logistics или их виджет выбора ПВЗ.
- **Тексты документов** (`src/lib/legal.ts`) и **банковские реквизиты в счёте** (`src/pages/b2b/invoice/[id].astro`) оставлены заглушками в квадратных скобках, как в макете, — их готовят юрист и бухгалтерия.
- **Фото товаров:** настоящие фото лежат в `public/images/products/` (товар вырезан с фона, квадрат 1000×1000, WebP с прозрачностью). Заглушки остались у 7 товаров без фото: средство для полов 1 л, универсальное средство, против плесени, от накипи, жидкое мыло 500 мл, шампунь 1 л, бальзам. Новые фото загружайте в админке (JPG/PNG/WebP) — они сохраняются в `data/uploads/`.
- **Черновики:** 18 товаров есть на фото, но не было в макетах (гели 3 л, гели-концентраты, кондиционеры для белья, 5-литровые антижир, пятновыводитель и средство для посуды, WC-гель 1,5 л, средства для пола 5 л, хозяйственное мыло 1 л, пластификатор). Они скрыты с сайта: заполните цену и остаток в админке и включите «На сайте».
- **Почта:** письма о заказах по умолчанию идут на arm2730@mail.ru (меняется в «Настройках» админки). Письма отправляются с info@palada.shop через SMTP хостинга (`.env` на сервере). Кнопка «Отправить тестовое письмо» там же проверит отправку.
- Делайте резервные копии папки `data/` (база и загруженные файлы).

## Структура

```
src/
  styles/        tokens, components, icons, screens — дословно из макетов; site.css — адаптив и состояния
  lib/           db (схема + сид), catalog, cart, promo, orders, payments, auth, delivery, inn, legal, format
  components/    шапки, подвал, карточка товара, выбор ПВЗ, окно оплаты, шаг ввода кода, кабинет
  layouts/       Shop (витрина), Admin
  pages/         страницы и API (src/pages/api/*)
  scripts/       клиентские сценарии (корзина, избранное, вход)
  sw/            сборка для GitHub Pages: адаптер Astro, service worker, заменители модулей Node
scripts/         fonts.mjs (загрузка шрифта), build-pages.mjs, db-reset.mjs
app.cjs          точка входа для Passenger на хостинге
scripts/deploy.sh выкладка на хостинг lite-host
.github/         публикация на GitHub Pages
```
